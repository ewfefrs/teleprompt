# Telegram-бот продажи ключей премиума (Teleprompter G2)

Автономно принимает оплату и **сам выдаёт подписанный ключ активации, привязанный к устройству
покупателя**. Приложение проверяет ключ публичным ключом (`LicenseManager.kt`) и включает премиум
только на том устройстве, чей Device ID зашит в ключ. Работает в любом магазине/сборке (Google
Play, RuStore, прямой APK), т.к. приложение ничего не «продаёт» — только активирует ключ.

## Что уже сделано (мной)
- Пара ключей EC P-256 **сгенерирована**. Публичный ключ **уже вшит** в приложение
  (`LicenseManager.PUBLIC_KEY_B64`). Приватный ключ — в `license_private_b64.txt` (в `.gitignore`).
- Проверено на реальном устройстве: ключ для «своего» Device ID активирует премиум, для чужого —
  нет.
- **Осталось только:** указать хэндл бота и запустить бота.

> ⚠️ Приватный ключ был сгенерирован в рабочей сессии. Для максимальной безопасности можно
> перегенерировать пару (`python license.py genkeys`, удалив старый файл) и заменить
> `PUBLIC_KEY_B64` в приложении на новый. Тогда пара никогда «не светилась».

## Настройка
1. Зависимости:
   ```
   pip install -r requirements.txt
   ```
2. Создай бота у [@BotFather](https://t.me/BotFather) → получи `BOT_TOKEN`.
3. В приложении: в [LicenseManager.kt](../../app/src/main/java/com/example/teleprompter/LicenseManager.kt)
   пропиши `TG_BOT` = хэндл своего бота (напр. `@my_premium_bot`) и пересобери приложение.
4. Приватный ключ для подписи — передай боту через переменную окружения (значение из
   `license_private_b64.txt`):
   ```
   set LICENSE_PRIV_B64=<строка из license_private_b64.txt>     # Windows (cmd)
   $env:LICENSE_PRIV_B64="<строка>"                              # PowerShell
   export LICENSE_PRIV_B64=<строка>                              # Linux/Mac
   ```

## Запуск
```
BOT_TOKEN=123:ABC LICENSE_PRIV_B64=<...> PRICE_STARS=150 python bot.py
```
Крипта (необязательно) — токен у [@CryptoBot](https://t.me/CryptoBot):
```
CRYPTOBOT_TOKEN=xxxx CRYPTO_ASSET=USDT CRYPTO_AMOUNT=2 BOT_TOKEN=... LICENSE_PRIV_B64=... python bot.py
```

## Как покупает пользователь
1. В приложении: **Настройки → Премиум → «Ввести ключ активации»** → копирует свой **Device ID**.
2. Пишет боту `/start`, присылает **Device ID** одним сообщением.
3. `/buy` (звёзды) или `/crypto` (крипта) → оплачивает.
4. Бот присылает ключ (для его устройства). Пользователь вставляет ключ в то же окно.
   На другом устройстве ключ не сработает.

## Ручная выдача / проверка (без Telegram)
```
python license.py selftest <device_id>     # подписать и проверить тестовый ключ
python license.py make <device_id> [note]  # выдать ключ вручную
```
Либо тем же занимается `tools/LicenseGen.java` (на JBR, без Python):
```
java tools/LicenseGen.java sign <PRIV_B64> <device_id> [note]
```

## Деньги / выплаты (для РФ)
- **Звёзды Telegram** → вывод в TON → обмен на рубли. Google/Apple в платеже не участвуют →
  блокировка выплат Google Play не мешает.
- **Крипта** (USDT/TON) — приходит сразу на твой Crypto Pay кошелёк.

## Безопасность / нюансы
- Ключ подписан асимметрично: в приложении только публичный ключ, подделать нельзя.
- Ключ **привязан к устройству** (Android ID) — его нельзя передать на другой телефон.
- Android ID меняется при сбросе к заводским / смене подписи APK — тогда нужен новый ключ.
- `issued_keys.log` — журнал выдач (user_id, device_id, ключ), в `.gitignore`.
- В сборке для **Google Play** не добавляй кнопку «Купить» со ссылкой на оплату — только
  «Ввести ключ» (сейчас так и есть). Ссылку на бота давай на сайте/в описании.
